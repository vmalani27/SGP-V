# Lab 2: Container Inspection & Lifecycle Management Assessment

## Scenario

Two containers have been initialized in your environment prior to the assessment:
- `mystery`: A background service container carrying configuration metadata.
- `expired`: A batch container that executed and terminated.

Your objective is to inspect runtime metadata, extract diagnostic logs, execute container state transitions without destroying underlying container entities, and cleanly tear down container resources.

This is an independent assessment. You are given operational constraints and acceptance criteria; you must determine the appropriate Docker CLI commands and inspection arguments to achieve the target state.

---

## Operational Specifications & Contract

### 1. State Inspection
- Determine the CLI command required to list all container entities across both active and terminated lifecycle states.

### 2. Configuration Extraction
- Inspect the running `mystery` container and extract its source base image name (e.g., `alpine` or `alpine:latest`).
- Save the exact extracted image name into `~/mystery-image.txt`.

### 3. Log Triage & Extraction
- Query the log output generated by the terminated `expired` container before it exited.
- Save its full standard output into `~/expired.log`.

### 4. Lifecycle Transitions
- Gracefully stop the `mystery` container.
- Confirm it has transitioned to an `exited` status.
- Restart the existing container entity so it resumes execution without creating a new container or altering its container identity.

### 5. Resource Teardown
- Terminate and delete both `mystery` and `expired` container instances.
- Ensure that zero container objects remain on the system.

---

## Acceptance Criteria

| Contract Requirement | Verification Check |
| :--- | :--- |
| **State Inspection** | Identify the command that displays active and terminated containers. |
| **Image Extraction** | `~/mystery-image.txt` contains the base image of `mystery`. |
| **Log Triage** | `~/expired.log` contains the stdout output of `expired`. |
| **Lifecycle Operation** | `mystery` was stopped and restarted as the same container entity. |
| **Clean Teardown** | Zero container instances exist on the host. |
